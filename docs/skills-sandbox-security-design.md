# Skills 安全执行沙箱设计（P2-01）

> 状态：设计基线；尚未实现沙箱，当前继续禁止执行用户上传代码。  
> 本文是实施门槛，不构成安全认证或运行时能力声明。

## 1. 安全目标与默认拒绝

自定义 Skill 是不可信代码。执行能力默认关闭，只有通过独立安全评审、隔离实现和攻击性测试后才允许启用。以下行为一律禁止作为“临时方案”：
- 在 API / Worker 主进程中使用 `eval`、`exec`、动态 import 或直接加载用户模块。
- 将普通 subprocess、同宿主 Docker 默认配置或 Python 虚拟环境称为安全沙箱。
- 将 Manifest 检查、JSON 样例契约检查称为 Skill 逻辑执行成功。
- 将 Skill 的“已登记”或“已启用”状态推断为“可运行”。

## 2. 威胁模型

需要防御的输入与行为：
- 恶意或失控代码：死循环、递归爆栈、内存耗尽、进程/线程泛滥。
- 主机访问：读取环境变量、密钥、配置文件、数据库、宿主文件和其他租户数据。
- 网络外传：任意 HTTP/DNS 访问、云元数据服务访问、内网探测。
- 权限提升：启动子进程、系统调用滥用、挂载宿主路径、访问 Docker socket。
- 数据越权：跨账号组读写、绕过业务 API、伪造身份或调用发布/互动动作。
- 供应链风险：恶意依赖、安装脚本、依赖投毒、版本替换。
- 输出攻击：超大输出、伪造日志、终端控制字符、敏感信息回显。
- 并发与生命周期：并发放大资源、超时后孤儿进程、取消竞态和重启后残留任务。

安全边界：即使容器或运行时被攻破，也必须尽量限制其对宿主、密钥、其他租户和外部网络的影响。

## 3. 推荐执行架构

1. API 层只接受版本化 Manifest、输入数据和经授权的能力声明；不接收任意文件作为可执行入口。
2. Skill Registry 保存来源、内容摘要、版本、签名/审核状态、权限、资源策略和状态变更审计。
3. 调度器向专用隔离执行服务提交不可变执行请求；主业务 API/Worker 不加载 Skill 代码。
4. 每次执行创建短生命周期、非特权、独立身份的隔离工作负载。
5. 输入输出经受限 JSON 协议传递；禁止挂载业务数据库、Cookie、模型密钥或宿主工作目录。
6. 结果经 schema 校验和业务权限校验后返回；业务副作用必须通过显式、逐项授权的受控工具 API。
7. 执行结束后销毁工作负载和临时存储，持久化结构化审计事件与诊断摘要。

隔离运行时优先采用独立主机/VM 或具备强隔离能力的 microVM。若采用容器，必须配合独立节点/用户命名空间、seccomp、AppArmor/SELinux、只读根文件系统、无特权、禁用宿主网络与宿主挂载，并单独进行逃逸风险评估。不得只依赖容器默认配置。

## 4. 最低资源限制（初始策略，需压测校准）

| 资源 | 初始上限 | 超限行为 |
|---|---:|---|
| 单次墙钟时间 | 30 秒 | 发送终止信号，宽限后强制杀死 |
| CPU | 1 vCPU | 限流并记录资源超限 |
| 内存 | 256 MiB | OOM 终止，记录原因 |
| 进程/线程 | 32 | 拒绝创建或终止任务 |
| 临时磁盘 | 64 MiB | 禁止继续写入并终止 |
| 标准输出/错误 | 各 1 MiB | 截断输出并记录截断标志 |
| 输入 JSON | 1 MiB | 请求校验拒绝 |
| 并发执行 | 每租户 2；全局需配置 | 排队或拒绝，不得无限创建 |

上述数值是第一版保守默认值，不是最终生产容量承诺。所有上限必须可配置、可审计且不可由 Skill 自行提高。

## 5. 权限模型

- 默认无网络、无子进程、无宿主文件访问、无环境变量继承。
- 不向执行容器注入平台 Cookie、API Key、数据库连接串或云凭证。
- 账号组身份由服务端签发的短时、不可伪造执行上下文表达，不接受 Skill 自报 tenant_id。
- 读权限必须映射到明确资源范围；写权限默认不存在。
- 发布、评论、关注、私信、删除、资金/额度扣减等高风险副作用永远不作为通用沙箱权限。
- 任何受控工具调用都需再次做租户隔离、权限校验、参数校验、幂等和审计。

## 6. 生命周期状态

状态必须分开保存和展示：
- 安装：built_in / registered / approved / rejected / removed。
- 启用：enabled / disabled。
- 可运行：blocked_no_sandbox / blocked_review / blocked_dependency / ready / runtime_unavailable。
- 执行结果：queued / running / succeeded / failed / timed_out / resource_limited / cancelled。

“已启用”仅表示管理员允许该 Skill 进入候选范围，不代表它已通过审核或可执行。自定义 Skill 在沙箱上线前必须始终为 `blocked_no_sandbox`。

## 7. 日志、诊断和审计

每次执行至少记录：
- execution_id、tenant_id、skill_id、skill_version、内容摘要。
- 发起人/触发源、权限集合、资源策略版本。
- 排队/开始/结束时间、耗时、CPU/内存峰值、输出字节数。
- 终态、退出码、超时/资源限制/取消原因。
- 工具调用名称、授权结果和脱敏参数摘要。
- 标准输出/错误的脱敏截断摘要，不保存密钥和完整敏感输入。

日志需防篡改、按租户授权读取、设定保留期限；错误响应向用户提供诊断 ID，不回显 traceback、环境变量、绝对路径或密钥。

## 8. 上线门槛

以下全部满足前不得开放自定义代码执行：
- 威胁模型评审及架构评审通过。
- 隔离运行时配置经自动化检查，默认拒绝网络、宿主挂载和特权。
- CPU、内存、时间、磁盘、进程数、输出大小限制均有超限测试。
- 沙箱逃逸、租户越权、密钥探测、网络探测、恶意依赖等攻击测试通过。
- 超时、取消、服务重启和执行器崩溃后无孤儿进程/资源泄漏。
- 审计日志完整，敏感信息扫描通过。
- 执行副作用仅能经显式授权工具，且幂等/权限回归通过。
- 生产灰度、告警、熔断、回滚预案就绪。

## 9. 当前实施状态

当前 IterWave 自定义 Skills 只允许登记 Manifest、校验输入输出契约和启停元数据。后端 API 明确返回 `execution_enabled=false`；Agent 编排遇到自定义 Skill 时拒绝执行。此限制应持续保留，直到第 8 节全部验收通过。
