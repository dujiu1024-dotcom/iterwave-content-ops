# PR 4：全局调度仪表盘

## 本次实现

- 新增 `GET /api/task-queue/summary`，直接对共享 `system.db` 的全局任务表执行 SQL 聚合，不读取或反序列化任务 payload。
- 统计全部六种队列状态：queued、running、succeeded、failed、cancelled、interrupted。
- 支持按创建日期范围、账号组 ID、任务类型、任务状态过滤。
- 返回每日任务总量、每日成功/失败量，以及有完整开始/结束时间任务的平均执行时长。
- 任务队列页增加全局调度仪表盘：状态分布、每日趋势、总量、运行/等待、成功/失败、平均执行时长和筛选器。
- 增加任务详情面板，展示任务归属、状态、时间、尝试次数、错误诊断、恢复/处理记录和管理操作审计。
- 统计与图表只呈现真实队列数据；没有执行进度字段的任务不会被推断出虚假百分比。

## 数据与性能约束

- 聚合查询在 SQLite 侧执行，避免将全部历史任务加载到 Python 或浏览器。
- 所有筛选值均通过 SQL 参数绑定；日期范围逆序返回 422，非法状态返回 422。
- 为创建时间及租户/任务类型/创建时间组合增加索引，日期范围条件使用半开区间，避免对筛选列套用函数。
- 每日趋势按任务创建时间归档；平均执行时长只使用 started_at 和 finished_at 均存在的成功、失败、中断记录。
- 图表最多展示筛选结果中最近 30 个有任务日期；统计卡片使用完整筛选结果。

## 权限边界与当前架构限制

当前项目认证模型是单一运营者共享访问口令/会话，`auth.audit_actor` 只能产生会话指纹或共享令牌标识；代码中尚无可验证的用户、角色、租户成员关系和全局管理员授权模型。因此本 PR 沿用既有全局运营者认证，不伪造“普通租户管理员”角色，也不宣称已实现多用户 RBAC。

- 新增统计接口为只读接口，不新增跨租户写操作。
- 取消、人工核验恢复和失败处理会写入任务操作审计表，并在详情中展示操作人、时间及说明；操作人采用现有会话指纹或共享令牌标识。
- 角色级授权与可识别自然人的审计主体仍需在独立身份/RBAC 基础上补齐。
- 仪表盘不新增平台发布入口，不调用发布服务。
- 取消、重试、处理/忽略动作均保留审计事件；取消状态更新与审计写入在同一数据库事务内完成，重试审计与子任务创建在同一事务内完成。
- 不能仅凭任务 ID 推导或授予新的租户访问权限。

## 验证

新增队列汇总单元测试，覆盖六态统计、按租户/类型/状态过滤、每日趋势、平均执行时长和非法日期范围。提交后由 GitHub Actions 执行仓库 CI；未取得 CI 结果前不标记测试通过。
