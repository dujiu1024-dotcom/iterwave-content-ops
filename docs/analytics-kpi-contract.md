# IterWave 运营分析 KPI 口径合同（P2-04）

> 状态：指标定义与数据源约束；Analytics 总览已按本合同只展示经营指标（2026-11-01 修订）。  
> 本文禁止用推算值冒充平台真实数据。

## 1. 时间与范围

所有 KPI 必须明确：
- 账号组范围：当前账号组或跨账号组；不得混用。
- 平台范围：单平台或所选平台集合。
- 时间范围：自然日/自然周/自然月或滚动 N 天，统一采用账号组业务时区。
- 统计对象：内容、草稿、发布记录、指标快照或目标。
- 更新时间与样本量。

## 2. 指标定义

| 指标 | 定义 / 公式 | 首选数据源 | 缺失值规则 |
|---|---|---|---|
| 内容生产量 | 统计窗口内创建的内容记录数 | `contents.created_at` | 表/字段不可用显示未知，不显示 0 |
| 草稿产出量 | 窗口内生成的草稿数 | `drafts.created_at` | 与内容生产量分开，避免跨平台变体重复计数 |
| 确认发布量 | 窗口内有用户确认时间的草稿数 | `drafts.user_confirmed_at` | 只代表用户确认，不推断平台回执 |
| 互动量 | views、likes、collects、comments、shares 分项总和 | `metrics` 快照 | 每个指标独立保留 NULL；未知不当作 0 |
| 平均互动率 | 按已定义平台口径计算的有效样本均值 | `metrics.interaction_rate` | 展示有效样本量；不能将不同平台原始计数直接合并比较 |
| 粉丝净增长 | 同一账号同一平台最新 followers - 窗口前最近可用基线；总览卡片为各平台净增长之和 | `account_snapshots` | 无同账号基线时该平台为未知、不计入合计；不能把不同账号快照相加冒充增长 |
| 目标完成率 | 后端目标进度引擎返回的 achievement_rate | `goals` / `/api/goals/summary` | 基线或当前值缺失则 NULL；不得前端自行补零 |

## 3. 必须区分的状态

- 未采集：数据尚未产生。
- 采集失败：有尝试但未得到有效数据。
- 未知/不适用：没有足够来源或分母。
- 真实零值：来源明确返回 0。

所有 KPI 卡片应显示统计窗口、数据更新时间和有效样本量；筛选条件变化时，卡片和明细必须使用同一范围。

## 4. 总览范围（经营指标）

IterWave 是自用运营工具，闭环为：生产 → 草稿 → 用户手动发布 → 复盘 → 调整。
Analytics 总览只展示经营指标：

- 生产量：内容生产量、草稿产出量、确认发布量（`GET /api/analytics/business-summary`）。
- 互动：平均互动率（`/api/metrics` 有效样本）与近 30 天互动分项汇总（business-summary.interactions）。
- 粉丝增长：按平台净增长明细与合计（business-summary.followers_growth_by_platform）。
- 目标完成率：`GET /api/goals/summary`。

明确不在总览展示、`business-summary` 也不返回的指标：

- 「草稿确认发布率」「平台发布成功率」：属于 SaaS 发布漏斗口径；前者分母易被误读为平台成功率，后者缺少平台权威回执，均已移除（字段 `publish_eligible`、`draft_publish_confirmation_rate`、`platform_publish_success_rate`、`platform_publish_success_note` 已删除）。
- TTV、7 日激活率、首次发布率、数据回流完成率、快速体验完成率、周采纳发布数、周有效复盘数等增长/激活指标：不进入经营总览。`/api/activation/metrics` 接口本身保留（快速体验与周报相关测试仍依赖），Analytics 页面不再调用。

“指标采集记录数”（`/api/metrics` total）是采集记录数，不代表生产量或发布量，只在“详细数据”视图分页中出现。

## 5. 验收要求

- 同一筛选条件下，页面 KPI 与数据库/API 聚合结果逐项一致。
- 内容、草稿、确认发布、平台回执不混为一个数字。
- 所有 NULL/失败/真实零值语义有自动化测试。
- 单平台与跨平台统计均有样例测试，跨平台不可比指标不进行简单求和或平均。
- 统计时区、窗口边界、去重规则有测试。
