# 子目标树、依赖门禁与子目标生产计划

## 1. 目标与边界

本模块在平台子计划版本内建立正式业务目标树。目标不等同于策略阶段：阶段描述执行节奏与策略步骤；子目标描述业务结果、验收标准和依赖关系。

本模块负责：
- 子目标父子树、排序、优先级及目标类型；
- 同版本目标依赖、循环检测和服务端状态门禁；
- 目标验收、证据历史和版本隔离；
- 目标级生产计划，以及生产任务与具体子目标的绑定。

本模块不负责批量创建生产线或批量内容任务。生产计划是后续生产编排的动态输入，不是一次性执行命令。

## 2. 目标类型与验收

| 类型 | 用途 | 通过条件 |
|---|---|---|
| quantity | 可计数的产出目标 | 必须提交实际数量，且不低于目标数量 |
| business | 业务结果目标 | 人工提交非空证据并确认 |
| effect | 效果目标 | 人工提交效果证据并确认 |
| quality | 内容/交付质量目标 | 人工提交质量证据并确认 |
| capability | 资料、账号、能力建设目标 | 人工提交建设结果证据并确认 |

客户端不能直接写入 `completed`。验收 API 只接受 `passed`、`failed`、`needs_review`，由服务端映射为目标状态。证据保存在 append-only 表，禁止更新和删除。

## 3. 状态

- `ready`：依赖全部通过，可进入生产或验收。
- `blocked`：至少一个前置目标尚未完成。
- `in_progress`：关联生产任务已领取。
- `completed`：服务端验收通过。
- `failed`：人工验收未通过。
- `needs_review`：证据不足，等待补充复核。
- `cancelled`：停止该目标。
- `draft`：预留草稿状态；正常创建后由依赖计算进入 ready/blocked。

失败和待复核状态不会被依赖刷新覆盖。前置目标通过后，阻塞目标才会重新进入 ready。

## 4. 依赖与生产门禁

依赖只能指向同一 `sub_plan_version_id` 下的其他目标。服务端同时检查依赖图和父子树是否有循环。

创建生产任务时：
1. 生产任务必须引用其轮次绑定的阶段和子计划版本。
2. 若阶段只有一个启用生产计划的目标，系统自动绑定该目标。
3. 若阶段有多个生产目标，调用方必须明确传入 `sub_goal_id`。
4. 目标必须处于 ready/in_progress，生产计划必须启用，且所有前置目标必须 completed。
5. 领取任务时再次校验依赖，防止任务入队后前置条件变化。
6. 任务领取时应将 ready 目标更新为 in_progress，并把目标定义及生产计划快照冻结到任务输入快照（生产任务接入由工作任务 3 协调完成）。

已完成、失败、待复核或依赖未通过的目标不能继续创建/领取其生产任务。旧任务在升级后若尚未绑定目标，领取时仅在该阶段恰好有一个生产目标时自动补绑；多个目标时 fail closed。

## 5. 版本与历史

所有目标绑定具体子计划版本。草稿版本允许创建和编辑目标；当前生效版本允许验收目标及动态调整生产计划。已完成目标不可原地修改，应通过新子计划版本重新定义。

迁移只增加目标相关表和 `production_tasks.sub_goal_id`，不回写历史策略阶段，不把历史阶段自动转换为子目标。旧版本目标、验收证据和任务快照保留原绑定。新版本不会继承旧版本完成状态。

## 6. 数据表

- `sub_goals`：目标定义、父级、类型、排序、优先级、验收条件和服务端状态。
- `sub_goal_dependencies`：目标依赖边。
- `sub_goal_evidence`：追加式验收证据。
- `sub_goal_production_plans`：目标级内容方向、建议数量、资源、执行条件和验收关联。
- 生产任务目标绑定：建议由工作任务 3 在共享任务模型中增加 `sub_goal_id`，并在创建/领取时调用本模块门禁服务；当前 MR 仅提供门禁服务接口，等待并行任务协调。

## 7. API

- `GET /api/subplans/{sub_plan_id}/goals?version_id={id}`
- `POST /api/subplans/{sub_plan_id}/goals`
- `PATCH /api/subplans/{sub_plan_id}/goals/{goal_id}`
- `PUT /api/subplans/{sub_plan_id}/goals/{goal_id}/production-plan`
- `POST /api/subplans/{sub_plan_id}/goals/{goal_id}/acceptance`

写目标定义仅限子计划草稿版本；生产计划允许草稿或当前生效版本；验收仅限当前生效版本。

## 8. 迁移、恢复与验收

迁移 148 仅新增子目标相关表、索引和触发器；不修改现有生产任务表。数据库启动迁移器在执行前会备份现有数据库；迁移失败会回滚当前迁移事务。回滚应用代码时保留新增表和历史数据，不应手工删除目标证据。若必须回退数据库，应从迁移前备份恢复，并先确认迁移后是否已产生新的目标/证据/任务关联。

自动化测试覆盖目标依赖、数量验收、父子与依赖循环、跨版本引用、排序、客户端状态越权、证据状态留存、任务目标绑定和领取时门禁。部署验收还需执行后端完整测试、前端构建、数据库结构审计，以及至少一次真实子计划版本的目标生产门禁验证。
