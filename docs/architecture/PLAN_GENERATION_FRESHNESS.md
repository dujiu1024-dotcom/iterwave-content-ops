# 母计划战略输入指纹与版本语义

## 目标

母计划是否仍可生成/审核，取决于真正影响经营决策的战略输入，而不是内容生产过程中不断增长的统计数据。系统保留完整经营诊断快照用于审计，同时使用单独的战略输入投影判断母计划依据是否仍然有效。

## 战略指纹白名单

由 `src/core/strategy_governance.py::collect_strategy_governance` 构造，使用规范化 JSON（UTF-8、排序键、紧凑分隔符）计算 SHA-256。

1. **账号组北极星**
   - 当前 `effective` 版本的版本 ID、版本号和完整快照。
   - 没有生效版本时值为 `null`；AI 和人工母计划创建均拒绝继续，提示先建立并确认北极星。
   - 版本切换即使文本恰好相同，也会因版本 ID/版本号变化而触发重新诊断。

2. **资源基线稳定资源**
   - 来自 `build_resource_baseline` 的资源条目、缺口及状态摘要。
   - 保留业务档案版本、业务目录条目、原始素材及授权/隐私/可读性/完整性/新鲜度状态、素材缺口、模板/技能与生产能力资源。
   - 资源条目保留来源类型、来源 ID、状态及决策所需详情；显式排除 `updated_at` 使用时间戳，避免素材被生产任务引用时仅因使用记录更新而使母计划失效。业务档案版本、资源状态、授权/隐私/质量字段和详情变化仍会改变指纹。
   - `historical_output`、`historical_performance` 和 `historical_content` 三类生产派生数据明确排除：新增内容、草稿、生产轮次和效果数据属于生产期派生信息，不应单独使母计划草稿失效。

## 变更语义

| 变更 | 生成/审核行为 |
|---|---|
| 新增内容、草稿、生产轮次、发布进度或历史效果统计 | 不改变战略指纹；允许沿用已确认诊断，并保留完整诊断快照供审计 |
| 业务档案、目录、素材授权/隐私状态、资源缺口或生产能力变化 | 战略指纹变化；拒绝生成/审核，要求重新分析并确认 |
| 北极星版本切换 | 战略指纹变化；拒绝生成/审核，要求重新分析并确认 |
| 最新诊断报告被替代、撤销或版本变化 | 生成审核时重新核验诊断 ID、版本和 confirmed 状态；不匹配即拒绝 |
| 母计划生效版本在生成期间变化 | 通过 Store 的 generation guard 拒绝写入；不覆盖现有草稿 |

旧版诊断没有战略投影时，采用旧的完整来源指纹比较；不满足时要求重新分析，避免把无法追溯的旧快照当作有效依据。

## 版本消费链路

- 经营诊断快照持久化 `strategy_governance`，诊断提示词直接消费它。
- AI 母计划提示词消费当前战略投影；生成元数据保存战略指纹、北极星版本 ID/号及资源基线快照。
- AI 草稿审核在激活事务内复验诊断 ID/版本/状态、战略指纹、母计划基准版本和草稿绑定的北极星版本。
- AI 生成必须使用最新已确认诊断；人工创建不依赖 AI 诊断或模型，但与 AI 路径共享已确认北极星和资源基线门禁。人工输入本身是策略草稿依据，模型不可用时仍可创建人工草稿。
- 母计划审核生效时，Store 冻结资源基线快照；母计划版本行冻结北极星快照/版本引用。
- 自动和手动 AI 子计划拆解均读取该母计划行绑定的北极星快照及该母计划固化的资源基线，不重新读取一个可能已经变化的当前版本。
- 历史母计划缺少任一绑定快照时，AI 子计划拆解明确拒绝并提示补齐战略版本，不以当前北极星/资源基线静默替代历史依据。

## 目标树命名

数据库枚举 `goal_level=north_star` 继续兼容历史数据，但前端和 API 校验错误文案统一称为“账号组经营目标（目标树顶层）”。“账号组北极星”专指长期定位/战略档案，避免与目标树顶层目标混淆。
