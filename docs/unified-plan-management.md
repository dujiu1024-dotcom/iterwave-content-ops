# 统一计划模型职责

## 唯一战略计划入口

战略计划只能由「计划管理」维护：

1. `master_plan_versions`：母计划的不可变版本，定义终极目标和总体约束。
2. `sub_plans` / `sub_plan_versions`：按平台拆分的执行策略及版本。
3. `sub_plan_stages`：子计划中的策略步骤、完成条件和依赖。
4. `production_lines` / `production_line_versions`：每个平台子计划对应的生产线及已审核版本。

不能由内容日历或 `/api/content-plans` 创建第二套战略计划。

## 生产批次和任务

- `spiral_rounds` 是实际生产批次，必须绑定母计划版本、子计划版本、策略步骤和生产线版本。
- `production_tasks` 是批次内的独立内容生产任务，创建时复制上述来源标识和输入快照。
- `contents` 通过 `production_task_id` 回链到生产任务，保留任务与内容成品的一对一归属。
- 新任务缺少生产线版本时，应用层和数据库触发器都会拒绝创建。迁移前已有的无生产线历史任务不被改写。

## ContentPlan 的新定位

`content_plans` 不再是战略计划，也不再创建新记录。它作为旧版独立内容计划的历史批次/排期投影保留：

- 允许读取历史计划、轮次、草稿和状态。
- 只允许修改历史批次的展示排期日期。
- 禁止新建、修改战略字段、独立启动生产、手工关联草稿、取消、归档和恢复。
- 历史轮次的策略归属从 `spiral_rounds` 回填到 `content_plan_rounds` 快照列。

迁移 142 使用三种状态避免伪造历史关系：

| 状态 | 含义 |
| --- | --- |
| `attributed` | 母计划、子计划版本、策略步骤和生产线版本关系完整且一致 |
| `manual_review` | 找到了轮次，但关联链不完整或不一致 |
| `legacy_unattributed` | 原始轮次不存在，无法确认来源 |

归属快照字段不设置外键约束，是为了保留历史孤儿 ID 供人工核查，避免升级时因旧数据不完整而失败。新生产任务的规范关联仍由既有数据库关系完整性触发器及新增生产线门禁保护。

## 内容日历职责

内容日历只负责：

- 展示历史批次和已生成内容。
- 展示内容排期、待排期草稿和执行状态。
- 调整内容成品允许调整的发布时间。
- 引导用户回到计划管理修改战略计划。

新的生产轮次和任务仍由计划管理中的已审核生产线创建，任务级失败、重试和恢复由生产监控处理。
