## 1. 第二阶段：核心业务闭环

### 1.1 B-01 统一待办中心 — 未完成，P1

- 在主整改分支的 API 路由中未发现统一待办聚合端点（检索 `/api/todos` 无结果）。
- `GlobalOperations.tsx` 当前异常区展示的是全局队列中的 failed/interrupted 任务，不等同于待办中心；它尚未统一汇总账号失效、图片失败、热点采集失败、待审核和超时等多种事项。
- 下一步：先定义统一待办 DTO、来源适配器、处理状态持久化和操作权限，再接入首页数量与运营中心列表。不能仅将多个列表前端拼接后宣称闭环。

### 1.2 B-02 异常分页与筛选 — 部分完成

- 全局队列已支持 active/failed 数据库分页和独立状态聚合；任务类型可与 failed scope 组合筛选。
- 尚需补足按账号组、平台、失败时间、原因关键字和处理状态的完整筛选契约，并验证异常详情关联。
- 不得把分页列表等同于完整待办处理能力。

### 1.3 B-03 失败任务安全恢复 — 有持久化恢复机制，但无人工重入队闭环

源码证据：`src/core/task_queue.py`：
- 表状态仅允许 queued/running/succeeded/failed/cancelled/interrupted（约 L85-L105）。
- `enqueue()` 明确拒绝自动重试，`max_attempts` 必须为 1（约 L177-L190）。
- 服务重启和租约过期会将 running 转为 interrupted，并要求核实平台侧结果（约 L392-L410、L449-L460）。
- 当前队列没有将 failed/interrupted 任务安全重新入队的通用方法；队列 API 的恢复设计必须保留原 tenant、payload、execution_snapshot，并建立 retry lineage 与人工确认审计。

结论：现有“不自动重放”是合理的安全保护，不应简单改成自动重试。缺口是有核验凭证、幂等保护和审计的人工恢复工作流。

### 1.4 B-04 通知与审计 — 部分功能存在，存在一个需要修复的关联范围问题

源码证据：`src/api/main.py`：
- `GET /api/notifications` 目前支持 level、page/page_size；未见 read/unread 筛选或单条/批量已读接口（约 L6463-L6485）。
- `POST /api/task_runs/{run_id}/resolve` 在收口 pending_verify 后，按 platform 更新该平台所有 pending_verify 的 ops_logs（约 L6426-L6461）。这可能把同平台其他未核实操作一并改为 success/failed，关联范围过宽。
- 下一步：给 task_runs 与 ops_logs 建立明确关联 ID；仅更新对应记录；增加并发/同平台多条待核实回归测试；通知补齐已读状态与审计事件。

### 1.5 C-01 账号入口 — 已开发，待自动化验证

账号页面和侧栏入口已存在；不重复开发。删除账号登记与平台登录态目前是分离动作，需在产品上明确语义。

### 1.6 C-02 账号昵称、头像与平台身份 — 仅人工登记，未完成自动采集

源码证据：
- `web/src/pages/Accounts.tsx` 明确标注“账号身份备注（手动登记）”，只有昵称/备注名、账号标识和备注字段；没有头像字段或平台资料自动同步流程。
- `src/api/main.py` 的 `platform_accounts` CRUD 仅保存 account_handle、display_name、status、notes（约 L7323-L7396）。
- 同一账号组每个平台限制一条登记记录（约 L7341-L7355）；这与当前每账号组每平台一个登录态的模型一致，但不能表达同一账号组同平台多身份。
- 结论：手动登记可作为临时识别能力；平台允许时仍需采集真实昵称、头像、平台 ID，并明确采集失败状态。不可伪造头像或昵称。

### 1.7 C-04 账号状态真实化 — 部分完成

- 账号页当前可见状态映射主要为 logged_in、logging_in、not_logged_in。
- 需要补充“已配置/已启用/登录失效/登录未知/不可运行”等区分，并核对实际 Cookie/会话检测是否支持失效识别；不能把“有账号登记”推断为“已登录”。

### 1.8 D-01 / D-02 / D-04 生产输入与资产追踪 — 需要继续专项审查

- 生产页面已能选择内容结构模板；生产执行器生成内容时会将 template_data 传入生成函数，contents 写入 template_id。
- 当前源码证据尚不足以证明每篇内容都固化了账号画像、行业模板、观点、外部参考的 ID/版本，以及模型参数快照。
- 下一步：沿自动生产和手动生产两条入口分别追踪输入构建函数、提示词组装、contents/drafts 持久化结构；对每项资产做“创建/修改后下一篇内容是否实际读取”的集成测试。

### 2.6 E-03 / E-04 Skills — 仅契约验证，不是统一注册和安全执行

- 自定义 Skill 需新增、编辑、启停、版本和能力状态。
- 独立测试需在隔离环境中执行，禁止触发真实发布、真实账号动作或意外扣额。
- 在安全沙箱和权限模型落地前，不得将“Skill 测试通过”解释为 Skill 逻辑执行成功。

### 2.7 E-05 热点来源 — CRUD 部分完成，单来源试抓取未完成
