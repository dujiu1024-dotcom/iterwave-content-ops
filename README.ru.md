# IterWave — система управления визуальным контентом на базе ИИ

[English](README.md) · [Китайский (упрощённый)](README.zh-CN.md) · [Русский](README.ru.md) · [Японский](README.ja.md) · [Французский](README.fr.md) · [Немецкий](README.de.md)

> **Ранняя предварительная версия** — проект с открытым исходным кодом находится в активной разработке. Фактический статус функций определяется кодом, тестами и проверками в целевой среде.

IterWave — рабочая среда для авторов, публикующих текстово-графический контент на нескольких платформах. Она объединяет поиск тем, планирование, подготовку материалов под платформы, контроль качества, публикацию с подтверждением человека и анализ результатов в единый отслеживаемый процесс.

## Основные принципы

- **Приоритет текстово-графического контента:** темы, тексты, карточки изображений, контроль качества и анализ.
- **Производство на основе планов:** общий план, планы для отдельных платформ, зависимости этапов и состояния выполнения управляют производством.
- **Публикация под контролем человека:** автоматизация может подготовить и сохранить черновик, но не нажимает кнопку публикации.
- **Прослеживаемость:** сохраняются версии планов и материалов, состояния задач, результаты выполнения и основания анализа.
- **Локальный контроль:** оператор управляет учетными данными, конфигурацией, базой данных и материалами.

## Рабочий процесс

```text
Библиотека тем / Позиционирование аккаунта / Поиск трендов
                         ↓
                   Общий план и под-планы
                         ↓
                Оркестрация и выполнение этапов
                         ↓
             Тексты и карточки для каждой платформы
                         ↓
                   Проверка качества и черновик
                         ↓
                  Публикация вручную
                         ↓
              Сбор данных → Анализ → Итерация
```

## Поддерживаемые платформы

Xiaohongshu, Douyin, Kuaishou и WeChat Channels (сценарии текстово-графического контента). Реальные возможности зависят от интерфейсов платформ, прав аккаунта и изменений пользовательского интерфейса; рабочие процессы необходимо проверять в целевой среде.

## Технологии

| Уровень | Технологии |
|---|---|
| Серверная часть | Python 3.11+, FastAPI, Pydantic v2 |
| Хранение данных | SQLite, версионируемые миграции схемы |
| Планирование и выполнение | APScheduler, глобальная очередь задач, изолированные Worker-процессы |
| Автоматизация браузера | Playwright (сохранение черновиков и сбор данных только для чтения) |
| Интерфейс | React 18, TypeScript, Vite |
| Обработка изображений | Pillow, OpenCV, NumPy |

## Быстрый запуск

### Серверная часть

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn src.api.main:app --reload
```

Подготовьте конфигурацию на основе `config/config.yaml`. API-ключи, cookie и токены храните только в локальной конфигурации окружения — не добавляйте их в репозиторий.

### Интерфейс

```bash
cd web
npm install
npm run dev
npm test
npm run build
```

## Развертывание и безопасность

- До первого запуска задайте надежный случайный `ITERWAVE_BOOTSTRAP_TOKEN` и установите постоянный пароль через процедуру инициализации. После завершения удалите bootstrap-токен.
- Для публичного развертывания используйте HTTPS. Не включайте `ITERWAVE_ALLOW_LOCAL_BOOTSTRAP=1` в публичной среде.
- Ограничьте доступ к конфигурации, базе данных и каталогам сессий учетной записью ОС, от имени которой работает сервис.
- APScheduler пока не поддерживает выбор лидера между процессами. Используйте один Uvicorn worker и не задавайте несколько `--workers`.
- По умолчанию глобальная очередь использует один Worker и последовательное выполнение FIFO. Параллельную работу групп аккаунтов включайте только после оценки последствий жесткого тайм-аута процесса.
- Задачи, прерванные жестким тайм-аутом или завершением Worker, автоматически не запускаются повторно. Сначала проверьте результат на платформе.
- Автоматические комментарии, ответы и подписки по умолчанию отключены. Перед включением проверьте правила платформ и разрешения аккаунта.
- Playwright сохраняет черновики. Фактическую публикацию подтверждает пользователь.

## Структура репозитория

```text
src/
  core/       Машины состояний, версии планов, очередь задач, планирование, восстановление, аналитика
  adapters/   Адаптеры платформ
  api/        Маршруты FastAPI и жизненный цикл приложения
  vendor/     Сторонний код с сохранением исходных лицензий
web/          Интерфейс React
migrations/   Миграции схемы базы данных
tests/        Серверные тесты
config/       Шаблоны конфигурации без реальных секретов
```

## Статус разработки и проверки

Проект продолжает активно разрабатываться. Успешные тесты репозитория не означают, что интеграции с реальными платформами проверены полностью. В целевой среде с соответствующими аккаунтами, сетью и учетными данными модели необходимо проверить:

- Реальный вход, сохранение черновиков и чтение данных на всех четырех платформах;
- Полный цикл работы модели: генерацию текста, создание карточек изображений и проверку качества;
- Полный цикл от сбора данных после публикации до анализа и выполнения стратегии следующего раунда.

Изменения кода должны сопровождаться тестами. Не помещайте учетные данные, пользовательские данные или состояние реальных аккаунтов в журналы и репозиторий.
