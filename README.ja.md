# IterWave — AI画像・テキストコンテンツ運用ワークスペース

[简体中文](README.md) · [English](README.en.md) · [Русский](README.ru.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

> **Early Preview** — 開発を継続中のオープンソースプロジェクトです。各機能の実際の状態は、コード、テスト、および対象環境での検証結果を確認してください。

IterWave は、複数プラットフォームで画像・テキストコンテンツを発信するクリエイター向けの運用ワークスペースです。テーマの発見、コンテンツ計画、プラットフォーム別制作、品質チェック、人による公開確認、成果分析を追跡可能なワークフローとして統合します。

## 基本方針

- **画像・テキストを中心に設計：** テーマ、文章、画像カード、品質チェック、運用分析に注力します。
- **計画駆動の制作：** 全体計画、プラットフォーム別サブ計画、工程依存関係、実行状態によって制作を進めます。
- **公開操作は人が管理：** 自動化は下書きの準備・保存まで行い、公開ボタンは自動でクリックしません。
- **追跡可能性：** 計画・コンテンツのバージョン、タスク状態、実行結果、分析根拠を記録します。
- **ローカル優先：** 認証情報、設定、データベース、コンテンツ資産は運用者が管理します。

## ワークフロー

```text
テーマライブラリ / アカウント方針 / トレンド発見
                         ↓
                    全体計画とサブ計画
                         ↓
                  工程の編成と依存実行
                         ↓
              各プラットフォーム向け文章・画像カード
                         ↓
                    品質チェックと下書き保存
                         ↓
                       ユーザーによる公開確認
                         ↓
                 データ収集 → 分析 → 戦略の反復
```

## 対応プラットフォーム

小紅書（Xiaohongshu）、Douyin、Kuaishou、WeChat Channels（画像・テキスト形式）。実際の対応範囲は各プラットフォームのインターフェース、アカウント権限、UI変更に依存します。実アカウントでの動作は対象環境で検証してください。

## 技術スタック

| レイヤー | 技術 |
|---|---|
| バックエンド | Python 3.11+、FastAPI、Pydantic v2 |
| データ保存 | SQLite、バージョン管理されたスキーママイグレーション |
| スケジューリング・実行 | APScheduler、グローバルタスクキュー、分離 Worker |
| ブラウザー自動化 | Playwright（下書き保存・読み取り専用データ収集） |
| フロントエンド | React 18、TypeScript、Vite |
| 画像処理 | Pillow、OpenCV、NumPy |

## クイックスタート

### バックエンド

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn src.api.main:app --reload
```

`config/config.yaml` を参考に設定してください。API キー、Cookie、トークンはローカル環境設定に保管し、リポジトリにコミットしないでください。

### フロントエンド

```bash
cd web
npm install
npm run dev
npm test
npm run build
```

## デプロイとセキュリティ

- 初回デプロイ前に強度の高いランダムな `ITERWAVE_BOOTSTRAP_TOKEN` を設定し、初期化フローで正式なアクセスパスワードを設定してください。初期化後はブートストラップトークンを削除します。
- 公開環境では HTTPS を使用し、`ITERWAVE_ALLOW_LOCAL_BOOTSTRAP=1` を有効にしないでください。
- 設定、データベース、セッションの各ディレクトリへのアクセスをサービス実行ユーザーに限定してください。
- APScheduler はプロセス間のリーダー選出に未対応です。Uvicorn worker は 1 つだけ使用し、複数の `--workers` を設定しないでください。
- グローバルキューは既定で Worker 1 つ、FIFO の逐次実行です。ハードタイムアウトがプロセス全体に及ぼす影響を評価したうえで、アカウントグループ間の並列実行を有効にしてください。
- ハードタイムアウトや Worker 終了で中断されたタスクは自動再実行されません。復旧を判断する前にプラットフォーム側の結果を確認してください。
- 自動コメント、返信、フォローは既定で無効です。有効化する前にプラットフォーム規約とアカウント権限を確認してください。
- Playwright による自動化は下書き保存までです。実際の公開はユーザーが確認します。

## リポジトリ構成

```text
src/
  core/       状態機械、計画バージョン、タスクキュー、スケジューリング、復旧、分析
  adapters/   プラットフォームアダプター
  api/        FastAPI ルートとアプリケーションライフサイクル
  vendor/     上流ライセンスを保持したサードパーティコード
web/          React フロントエンド
migrations/   データベーススキーマのマイグレーション
tests/        バックエンドテスト
config/       実際の秘密情報を含まない設定テンプレート
```

## 開発・検証状況

プロジェクトは開発中です。リポジトリのテスト通過は、実プラットフォームとのエンドツーエンド検証を意味しません。対象アカウント、ネットワーク、モデル認証情報が利用できる環境で、次の項目を検証する必要があります。

- 4 プラットフォームすべての実ログイン、下書き保存、データ読み取り；
- モデル呼び出し、文章生成、画像カード制作、品質チェックの一連の処理；
- 公開後のデータ収集から分析、次の計画の実行までの完全なサイクル。

コード変更には関連テストを追加してください。認証情報、ユーザーデータ、実アカウントの状態をログやリポジトリに保存しないでください。
